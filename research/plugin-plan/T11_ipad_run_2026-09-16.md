## Findings (real, on device)
1. **TCC kill on first dictation tap** — `scripts/ios-device-deploy.sh` builds from the *committed* generated `Info.plist` without running
   `xcodegen`; Task-11 `project.yml` edits (NSMicrophoneUsageDescription) were not in the shipped plist → iOS terminated the app at mic access.
   Fixed by committing the regenerated metadata (`naked@2e0ca845`). Rule: after any `project.yml` change, run `xcodegen generate` and COMMIT.
2. **WDA taps are inert on this device** (element click and W3C pointer actions; WebView AND native document picker) while the a11y tree and
   screenshots work — earlier physical runs (2026-07-28) had working taps. Undiagnosed (automation mode / testmanagerd?). CDP `Runtime.evaluate`
   on an inspectable build drives the WebView fully; native sheets remain undriveable → relaunch via `devicectl` to dismiss.
3. **Toggle-stop ignored while `start()` is pending on the system mic prompt**: `useVoxisRuntime.stopActive` needs `activeSessionIdRef`, which is
   set only when `client.start()` resolves — the plugin's iOS start awaits `requestRecordPermission`; a stop tap in that window is a no-op and the
   session runs to the silence timeout. naked polish: remember the pending start and stop/cancel it once resolved (or plugin `stop_active`).
4. Settings `profileStatus` is computed at boot / after the UI import only — an out-of-band `apply_profile` shows «No API key» until relaunch.
5. naked app terminated once during the WDA run after a raw-touch tap on the Settings gear (~2m46s after an element click) — no crash log,
   sessions reattached; not reproduced.
6. Owner-visible: «Import from Voxis desktop» and the hotkey selector are meaningless on iOS (plugin has no hotkey backend there) → hide on mobile.
