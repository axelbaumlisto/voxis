## Findings

### F1 — HIGH — Tauri hooks `on_page_load` / webview-destroyed ⇒ `cancel_all(Hold)` are not implemented at all
- **Where:** `crates/tauri-plugin-voxis/src/lib.rs:169-213` (`Builder::new("voxis").invoke_handler(..).setup(..).build()` — no `on_page_load`, `on_event`, `on_webview_ready`, `on_drop`); `grep -n "on_page_load\|cancel_all\|Destroyed" src/*.rs` → only a doc-comment mention in `lease.rs:5`. No `cancel_all` helper exists on `SessionGuard`/`PluginState`; no test.
- **Why it matters:** The step text and plan §5 (`[R1-Safety S4]`, lines 94-95) list this as an acceptance item alongside the lease, not as optional: "Tauri-хуки `on_page_load` / web-content-process-terminated → `cancel_all(Hold)`". The lease only closes the mic after ≥3 s (+ up to 250 ms poll granularity); the hook is what makes a webview reload/WebKit-process death (naked F77) an *immediate* cancel. The worker's timeout while "scanning the filesystem for tauri sources" strongly suggests this was left for last and never landed.
- **Fix (small):**
  1. `SessionGuard::cancel_all_hold(&self)` (or `cancel_active_if(|s| s.mode == Mode::Hold)`): lock, if active session is `Mode::Hold` → `control_tx.send(ControlSignal::Cancel)` and, if `stage == Transcribing`, abort via `transcribe_abort` (same logic as `do_cancel`, factored into a shared fn so the two don't drift). Non-async, no await, returns immediately (the pipeline task does the cleanup).
  2. In `build()`: `.on_page_load(|webview, _payload| { if let Some(st) = webview.try_state::<PluginState>() { st.sessions.cancel_all_hold(); } })` and `.on_event(|app, ev| match ev { RunEvent::WindowEvent { event: WindowEvent::Destroyed, .. } | RunEvent::Exit | RunEvent::ExitRequested{..} => cancel_all_hold, _ => {} })`. Both `on_page_load` and `on_event` exist on `tauri::plugin::Builder` in Tauri 2 (the crate already compiles against it; iOS "web content process terminated" has no direct Tauri hook — `on_page_load` fires on the reload that follows, which is the documented intent; note that in a doc comment).
  3. Unit test on the helper (no Tauri runtime needed): Hold session active → `cancel_all_hold()` → outcome `Cancelled`, file deleted; Toggle session active → untouched.

### F2 — MEDIUM — `do_cancel` TOCTOU: cancel can be silently ignored and the audio still uploaded
- **Where:** `commands.rs` `do_cancel` (`stage_of` → then `signal(Cancel)` **or** abort-cell take) and `pipeline.rs::run_transcription` (`abort_cell` is set only *after* `tokio::fs::read(path).await` + `secrets.get` + client build).
- **Scenario A:** `stage_of` returns `Recording`; before `signal(Cancel)` lands, the guard loop exits on its own tick (silence/max/stream-died) → `finalize` → `Transcribing`. The `Cancel` send goes into a channel no one reads; `do_cancel` then awaits the outcome, which is a **full transcription** — the cancelled audio is sent to the cloud and a `voxis://result` with real text fires. `do_cancel` returns `Ok(())`, so the caller believes nothing was sent.
- **Scenario B:** `stage_of` returns `Transcribing` but `abort_cell` is still `None` (between `mark_transcribing` and `handle.abort_handle()` — a real window: async file read, secret lookup, reqwest client construction). `take()` yields `None` → nothing aborted → same result as A.
- **Why it matters:** `cancel` is the user's "do NOT send this" button; a cancel that returns `Ok` while the upload proceeds is a privacy-semantics bug, not just a race nit. Neither window is covered by tests (the existing cancel-during-Transcribing test aborts the handle directly after polling until it is `Some`).
- **Fix (small):** add a per-session `cancelled: Arc<AtomicBool>` (or `tokio_util::CancellationToken`-style flag) to `SessionHandles`, set unconditionally by `do_cancel` **before** signalling/aborting. In `finalize`: check it before `mark_transcribing` (→ treat as `Trigger::ExternalCancel`), and in `run_transcription` re-check right after storing the abort handle (`if cancelled { handle.abort() }`). Then `do_cancel` no longer needs the stage branch at all (send `Cancel`, set flag, abort if handle present, await outcome) — simpler and race-free. Add a test: signal Stop, then cancel while `abort_cell` is still `None` (e.g., via a `SecretStore` that blocks), assert mockito `expect(0)`.

### F3 — LOW — `finalize` emits `State::Error` and never returns to `Idle`, while `state()` already reports `Idle`
- **Where:** `pipeline.rs::finalize` (`emit(STATE_EVENT, if ok Idle else Error)`, then `sessions.end`).
- After an error the event stream is stuck on `error` until the next `start()` emits `recording`, but `do_state()` says `idle`. Either document `Error` as a transient terminal-for-this-session state in the contract, or emit `Idle` right after `Error`. Not blocking; just make the contract explicit.

### F4 — LOW — pipeline-task panic wedges the single-flight slot forever
- **Where:** `finalize` — `sessions.end(&id)` runs only on normal completion. A panic anywhere in the task (`serde_json::to_value(..).unwrap()`, a poisoned `StdMutex`) drops `RecFile` (good) and `outcome_tx` (callers fail closed — good), but the `SessionGuard` slot stays claimed → every subsequent `start()` returns `AlreadyRecording` until app restart. A small `scopeguard`-style drop guard that calls `sessions.end(&id)` covers it. Optional for this round; note in minors if deferred.

## Minors
- **M1 (DRY)** `pipeline::apply_dictionary` is a verbatim copy of `DictionaryStorage::apply`'s loop. The justification (that method loads from disk) is valid, but the right fix is a pure `voxis_core::storage::dictionary::apply_entries(text, &[(String,String)])` that both call. Out of 3b's file scope — file as follow-up for the voxis-core owner.
- **M2 (dead code)** `ActiveSession::started_at` / `ActiveSession::elapsed_ms` / `SessionGuard::elapsed_ms` are no longer used anywhere (duration now comes from `CaptureStats`). Remove.
- **M3 (test strength)** `hold_release_hold_five_times…` builds a fresh `SessionGuard`/`MockCapture` per iteration, so it cannot observe cross-session ABA by construction. Use one shared `SessionGuard`, send a `hold_lease` with the *previous* id after each restart, and assert `UnknownSession` + no `LeaseLost`.
- **M4 (contract clarity)** A too-short `stop()` (`duration_ms < min_recording_ms`) returns `GuardOutcome::Finalized` with empty text — indistinguishable from "transcribed to nothing". Document in `GuardOutcome::Finalized`'s doc (enum is fixed by the contract) or add `TooShort` in a contract bump.
- **M5 (trait contract for Task 4)** `guard_adapter::poll` feeds `LevelSample.peak` as `guard_step`'s `rms_peak`. `capture.rs` never states that `peak` must be *max per-chunk RMS since the previous sample* (`take_rms_peak` semantics) rather than peak sample amplitude. Add one sentence to `LevelSample.peak`'s doc, otherwise a real backend can feed values ~3-10× larger and the silence timeout will never fire. Also state "backends must publish ≥1 sample per 250 ms; 4 consecutive empty polls ⇒ StreamDied".
- **M6 (future secret caching)** `PipelineDeps.app_config.llm.api_key: String` (plaintext) is snapshotted from `PluginState.pipeline_config`. Empty today, but once Task 6/7 populate `LlmConfig` from a profile this would cache an LLM key in `PluginState`, contradicting `[R1-Safety S2]`. Note for Task 6/7: source the LLM key from `SecretStore` at call time like the transcription key.
- **M7** `sigkill_simulation_leaves_rec_dir_empty_after_fresh_init`: the pipeline task is still alive inside the same test runtime when `sweep()` runs, so it is really a "sweep deletes a file another owner still holds" test; fine, but the comment overstates the simulation.
- **M8** First-poll behaviour: `interval` fires immediately at t=0; because `start()` publishes `None`, `has_changed()` is true and the miss counter starts at the 250 ms tick, so StreamDied lands at exactly 1000 ms — the `<= 1_000` assertion is on the boundary. Consider `LIVENESS_MISSED_POLLS_LIMIT` semantics doc or assert `< 1_250`.
- Formatting drift (`\u2014` em-dashes re-encoded in comments): pre-existing, ignored per instructions.
