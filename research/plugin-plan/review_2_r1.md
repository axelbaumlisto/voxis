## Findings

No blockers. Everything below is Minor (non-blocking, fix-forward in a later step or leave).

- **Minor / data-integrity** — `crates/voxis-core/src/profile/mod.rs` `sync_providers` (≈ line 420-435): for an incoming provider id that does not exist locally, `storage.add(provider)` is called with the profile's own `builtin` flag. `ProvidersStorage::add` inserts `builtin` verbatim, and `remove` refuses builtins, so a profile carrying `builtin: true` for a non-seeded id plants an un-removable provider. Also `update` (no builtin guard in storage) lets a profile rewrite a seeded builtin's `api_url`. Both are only reachable by whoever holds the seal key, and `from_storage`→`apply_to` round-trip is faithful, so not blocking. Fix (1 line): `let p = LlmProvider { builtin: false, ..provider.clone() }; storage.add(&p)`; optionally skip `update` when `existing.builtin`.
- **Minor / secret hygiene** — `crypto.rs` `derive_key`/`encrypt`/`decrypt` and `mod.rs::seal`: the derived 32-byte key (stack array) and the serialized plaintext `Vec<u8>` (contains both API keys) are not zeroized after use. Consistent with the rest of the codebase (AppConfig holds `api_key` as a plain `String`), so acceptable for this step; `zeroize` on `key_bytes` + `plaintext` would be a cheap hardening later.
- **Minor / semantics** — `apply_to` ignores the *value* of `api_key_ref`/`llm_api_key_ref` (always writes under the `API_KEY_SECRET_NAME` constants) and, when `secrets.api_key` is `None`, does not clear a previously-stored secret in the sink (`SecretSink` has only `put`). Sqlite `api_key` *is* blanked unconditionally (correct). Behaviour is defensible ("import without a key keeps your existing key") but should be stated in the doc comment; the plan's `SecretStore` has `delete`, so Task 3+ can decide.
- **Minor / atomicity wording** — `apply_to` is transactional only at the validation boundary (nothing written if `validate_config` fails — verified, and tested). A storage failure after `config_storage.save` (e.g. dictionary file I/O) leaves partial state. Matches the plan's wording ("сначала валидация всего профиля, потом запись"), just don't oversell it as rollback.
- **Minor / doc drift** — `mod.rs` `CURRENT_VERSION`/`check_version` docs mention `from_json`, which doesn't exist. Also `VoxisProfile: Deserialize` is public, so a caller can bypass `check_version`; `open()` and `apply_to()` both call it, which is sufficient for this step, but the plugin import path (Task 3+) must not build a `VoxisProfile` via bare `serde_json::from_str` without calling it.
- **Minor / contract casing** — `contract/fixtures/profile-v1.json` mixes camelCase (`apiKeyRef`, `activePromptId`) with snake_case inside `llm.providers[]` (`api_url`, `default_model`) because `LlmProvider` is reused verbatim (no `rename_all`, out of scope to change). Consistent with the specta/frontend type already in use; flag so the contract doc for Task 3+ mentions it rather than someone "fixing" it and breaking parsing.
- **Minor / KISS** — `encode_base64url`/`decode_base64url` and the `base64 = "0.23"` dep are unused by this step (worker states so; step's dependency list did name base64). Adds a third `base64` major to `Cargo.lock` (0.21.7, 0.22.1 transitive + 0.23.1). Not wrong; could have been deferred to Task 7.
- **Minor / perf** — `sync_dictionary` deletes entries one index at a time; each `delete` rereads/rewrites the whole file → O(n²) for large dictionaries. Fine for realistic sizes (hundreds), note if dictionaries reach thousands.

## Checked and OK

1. **crypto.rs** — Format is exactly `b"VXP1" | kdf_tag(1) | salt(16) | nonce(12) | ct`, HEADER_LEN = 33; the full header slice is passed as AEAD `aad` on both `encrypt` and `decrypt`, so any header byte (magic, tag, salt, nonce) or ct byte flip fails Poly1305 → `Err` (tests: `tampered_header_byte_fails` hits salt byte 6, `tampered_ciphertext_byte_fails`, `bad_magic_errs`, `mismatched_key_source_kind_fails`). Salt and nonce both from `getrandom::getrandom` (CSPRNG) per `encrypt` call; with a fresh random salt the derived key is per-message, so nonce reuse is a non-issue even beyond the 96-bit random nonce. **Qr path**: `Hkdf::<Sha256>::new(Some(salt), k_qr)` with `info = b"voxis-profile-v1" || code` — ikm is k_qr only, the code is purely info; no code-only key path exists. Security with k_qr alone ≥ 2^128 as the plan requires. **Argon2id**: `#[cfg(not(test))] argon2_params()` uses `ARGON2_M_COST_KIB=65536, T=3, P=1`, output 32; the `#[cfg(test)]` reduced variant only applies when compiling voxis-core's own test target — a downstream crate's build (including tauri-plugin-voxis tests) gets production params. `Algorithm::Argon2id, Version::V0x13` explicit. `decrypt` validates length and magic before touching any primitive; the single `expect` on `try_into` is unreachable after the length check. Wrong code / wrong k_qr / wrong passphrase → clean `Err(ProfileError::Crypto)` with a fixed message (AEAD error discarded), no partial plaintext (AEAD is all-or-nothing). No `tracing`/`log` calls in the module.
2. **secret.rs** — `Secret(String)`: derives only `Clone, PartialEq, Eq`; manual `Debug` → `Secret([REDACTED])`; no `Display`, no `Serialize`/`Deserialize` anywhere in the crate (grepped `impl.*Serialize.*Secret`, `Secret.*Serialize`: none). Only `.0` access is inside `expose()`. `ProfileSecrets` derives `Debug` → redacted via `Option<Secret>`. The only `expose()` call sites outside tests are the two in `seal()` building the private `SealedPayload` DTO. `SecretSink::put` doc requires implementors not to log the value. Tests cover Debug on bare/Option/Vec/ProfileSecrets and that `serde_json::to_string(&profile)` never contains the key.
3. **ProfileConfig subset vs AppConfig** — Included: `cloud_provider`→`provider`, `model`, `api_url_override`, `language`, `translate_to_english`, `min_recording_ms`, `silence_timeout_ms`, `max_recording_ms`, `hotkey_hold_ms`, `llm.{enabled,provider,api_url,model,prompt}` + refs; `overlay.theme`→`theme` and `hotkey` promoted top-level. Nothing desktop-only leaked in; nothing the plan lists (decision 6) is missing.
4. **from_storage / apply_to** — `apply_to`: loads the current AppConfig, overlays only the profile fields, sets `api_key = ""` and `llm.api_key = ""` unconditionally, runs `crate::config::validate_config` on the whole merged struct, and returns `Validation` **before any** `save`/dictionary/provider/prompt/sink call (verified by reading the code path; test `apply_to_validation_failure_leaves_storage_untouched` checks config, dictionary and sink). Secrets go only to `secret_sink.put` (test also greps the raw `config.db` bytes for the key). `from_storage` reads `app_config.api_key`/`llm.api_key` into `ProfileSecrets` and emits only `_ref` markers (set iff non-empty). Dictionary/providers/prompts = **replace** semantics (stated in doc comments): dictionary full delete-then-add, providers/prompts remove-absent + update-existing + add-new, active prompt id set — a re-import does not duplicate entries (test `apply_to_syncs_dictionary_providers_and_prompts` verifies stale entries removed and exact dictionary equality). Builtin providers are never removed (storage would error) — sensible.
5. **Versioning** — `check_version` → `UnsupportedVersion { found }` with message "unsupported profile version 2 (this build supports version 1)"; called in `open()` and `apply_to()`. No `deny_unknown_fields`; `unknown_fields_are_ignored_forward_compat` test injects a new top-level key. Fixture `profile-v1.json`: synthetic values only (no `sk-`, `gsk_`, `@`), uses `apiKeyRef`/`llmApiKeyRef` refs, deserializes into `VoxisProfile` and passes `check_version` (`fixture_profile_v1_deserializes_and_is_version_1`).
