VERDICT: REJECT-FIX

Task 5 (guest-js `@voxis/tauri-plugin-voxis`) is substantially correct and the safety-critical items (CSP-safe static theme registry, pointercancel/lostpointercapture/blur → stop, lease heartbeat lifecycle, contract mirror) check out. Three fixable gaps keep me from APPROVE: (1) the plan's "не перекрывает клавиатуру iOS (`visualViewport`)" acceptance is only half-implemented — no `visualViewport.resize` re-clamp (and a `reposition()` method is referenced in a comment but doesn't exist); (2) `matchesHotkeySpec` covers a fraction of `voxis_core::hotkey` aliases and fails closed *silently*, so an imported desktop profile with e.g. `hotkey: "f13"`/`"super"`/`"altgr"` produces a hotkey that never fires; (3) combo release ordering leaves recording hanging up to 5 s. None require redesign — small edits + tests.

## Findings

**M1 — Medium — `src/overlay.ts:170-176`, `src/drag.ts:267` — no re-clamp on `visualViewport.resize`; plan acceptance gap.**
Position is clamped against `readEffectiveViewport()` only at `connectedCallback` and at drag end. When the iOS keyboard opens, `visualViewport.height` shrinks but nothing runs, so a bottom-anchored pill sits under the keyboard — exactly the case the plan calls out. The comment at overlay.ts:172 says "until the first `reposition()`" but no `reposition()` exists (`grep reposition src/overlay.ts` → only that comment). Fix: add `reposition()` (re-clamp current pos, write left/top) and call it from `window.visualViewport?.addEventListener("resize", …)` + `window.addEventListener("resize", …)`, remove in `disconnectedCallback`; add a jsdom test that mutates a mocked `visualViewport.height` and dispatches `resize`. (Note: `position: fixed` is relative to the *layout* viewport on iOS; when the keyboard is open you also need `+ visualViewport.offsetTop` — worth a comment even if not handled now.)

**M2 — Medium — `src/hotkey.ts:24-40, 93-106` — key-name table is a strict subset of `voxis_core::hotkey::parse_hotkey`, and unrecognised specs fail closed with no signal.**
Rust aliases (crates/voxis-core/src/hotkey/mod.rs:40-231) include `alt_gr`/`altgr`, `control_r`/`control_l`/`control`, `super`/`super_l`/`super_r`, `f1`–`f12`, `space`, `enter`/`return`, `tab`, `escape`/`esc`, `backspace`, `delete`/`del`, `home`, `end`, `page_up`/`pageup`, `page_down`/`pagedown`, `caps_lock`/`capslock`, `insert`, `pause`, `print_screen`/`printscreen`, `scroll_lock`/`scrolllock`, `num_lock`/`numlock`. TS handles only the 15 modifier names. A `VoxisProfile.hotkey` imported from desktop (Task 3 flow) that uses any of the others yields `() => false` — the user gets no hotkey and no error. `parseCombo` also drops `super` for single-key form though it accepts it as a combo modifier (Rust `HotkeyCombo::parse` also accepts `"command"`, TS doesn't). Fix: extend `SINGLE_MODIFIER_CODES` → `SINGLE_KEY_CODES` with the full alias→`KeyboardEvent.code` table (`AltRight` for alt_gr/altgr, `F1..F12`, `Space`, `Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, `CapsLock`, `Insert`, `Pause`, `PrintScreen`, `ScrollLock`, `NumLock`), add `command`; have `matchesHotkeySpec` (or `bindHotkey`) `console.warn` once on an unrecognised spec. Add a table-driven test over the Rust alias list.

**M3 — Medium — `src/hotkey.ts:100-106` — combo release order leaves recording running until the 5 s lost-keyup timer.**
For `"Ctrl+Shift+V"` the keyup predicate requires *all* modifiers still held and `key === "v"`. If the user releases Ctrl or Shift before V (very common), the Ctrl keyup has `key: "Control"` (no match) and the later V keyup has `ctrlKey: false` (no match) → `pressed` stays true for up to 5 s of extra recording. Fix: use a separate release predicate — on keyup release if `e.key.toLowerCase() === combo.key` **or** the released key is one of the required modifiers (`e.key` in `Control`/`Alt`/`Shift`/`Meta` and that modifier is part of the combo), regardless of remaining modifier state. Test: keydown Ctrl+Shift+V → keyup Control → expect `onReleased`.

**L1 — Low — `scripts/build-themes.ts:19-21` — doc comment claims a test that does not exist.**
"see guest-js's build-themes round-trip test, which diffs this directory" — there is no such test (`grep -rn build-themes __tests__` → nothing). Either add it (see decision below) or fix the comment.

**L2 — Low — `guest-js/package.json:21-22` + `scripts/build-themes.ts` — cwd-dependent output.**
`Bun.build` emits `// src/theme-engine/renderers/smoothing.ts` source comments relative to **cwd** (verified: `head src-tauri/themes/default/theme.js`). Byte-identity of both outputs therefore depends on `bun --cwd ../../..`. Any CI job or developer that runs the script from another directory produces a spurious diff in the checked-in `src-tauri/themes`. Fix: `process.chdir(ROOT)` at the top of `build-themes.ts` (one line, cwd-independent), keep `--cwd` as a no-op.

**L3 — Low — `src/overlay.ts:337-347` (Toggle mode) — `activeSessionId` never cleared when the plugin ends the session itself.**
Silence-timeout / max-duration / stream-died end a Toggle session server-side (`voxis://result` + state→idle) but the overlay still holds `activeSessionId`; the next tap calls `stop(staleId)` (fails, swallowed) instead of starting — user must tap twice. Fix: in `onState`, when state becomes `"idle"`/`"error"` with no in-flight `start`, set `activeSessionId = null` and stop the lease (or subscribe `onResult`).

**L4 — Low — `src/client.ts:113-126` — `dictate()` never settles on `cancel()`.**
If the session is cancelled (no `voxis://result`), the promise hangs and the listener leaks. Also the listener is attached *after* `start()` resolves; in Hold mode result can't arrive before `stop()`, so the race is benign today, but a start-then-immediate-`StreamDied` could be missed. Fix: attach `listen` before `start()`; on `cancel()` reject or resolve with `guardOutcome: "cancelled"` (the Rust side does emit a result for `Cancelled`? — if so document; if not, add a rejection path).

**L5 — Low — `__tests__/csp-bundle.test.ts:38` — hard dependency on `npx`.**
Bun-only CI images may lack `npx`. Prefer `join(PACKAGE_ROOT, "node_modules/.bin/tsc")` or `bunx tsc`. Also consider adding `new Function(`/`eval(` to the grep since `script-src 'self'` (no `'unsafe-eval'`) blocks those too.

## Decision question — 1.7 MB generated themes checked in under `guest-js/src/themes/generated/`

**Recommendation: accept checked-in (same convention as `src-tauri/themes`, 36 files already tracked), but add a drift guard.** Reasoning: (a) reproducibility — consumers of the package (tsc, vitest, harness) don't need Bun/root build graph to resolve imports; (b) repo bloat — +1.7 MB is the same cost already paid for `src-tauri/themes`, and the two dirs are byte-identical (`diff -rq` → IDENTICAL) so git delta-compresses well; (c) CI simplicity — `bun run test` already regenerates both dirs first, so drift shows up as a **dirty tree**, not a test failure. That last point is the gap: nothing *asserts* cleanliness. Fix (small): either a vitest that runs `build-themes.ts` to a temp dir and `diff`s against both checked-in dirs (what the build-themes.ts comment already claims exists — L1), or a CI step `bun run build:themes && git diff --exit-code src-tauri/themes crates/tauri-plugin-voxis/guest-js/src/themes/generated`. Do not gitignore: that would make `tsc`/registry imports fail on a fresh clone without Bun.

## Minors
- `themeBridge.api.params` is always `undefined` and `size` is the fixed 64×64 pill; the copied `theme.json` (which carries `params` and `overlay_width/height`) is never read. Builtin themes guard `api.params` (`api.params && typeof … === "object" ? … : {}`), so no crash, but themes designed for 320–340 px wide render into a 64 px circle. Consider reading manifest `params`/size from `generated/<id>/theme.json` in a follow-up.
- `startActive` swallows `start()` errors (`catch { activeSessionId = null }`) — permission-denied / `AlreadyRecording` are invisible to the host; expose an `onError` option or dispatch a `voxis-error` CustomEvent.
- `disconnectedCallback` does not `stopActive()` an in-flight session (Hold is rescued by LeaseLost in ≤3 s; Toggle relies on silence timeout). Consider best-effort `cancel()` on disconnect.
- `wireClientEvents`: if the element disconnects before `listen()` resolves, the resolved unlisten is never invoked (tiny leak).
- `overlay.ts` re-exports `DictationResult` type at bottom — redundant with `index.ts`'s `export * from "./types/contract"`.
- Doc comments are very long relative to code; not blocking.
