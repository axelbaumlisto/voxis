## Findings

### F1 — HIGH — `examples/host-min/scripts/host-min-smoke.sh` `start_fake_stt` / `run_scenario` (`port=$(start_fake_stt)`): fake-stt PID is lost → servers leak, cleanup/trap is a no-op for them
`start_fake_stt` does `"$fake_stt_bin" … & fake_stt_pid=$!` **inside a `$(...)` command substitution**, i.e. in a subshell. The parent's `fake_stt_pid` stays `""`, so `kill "$fake_stt_pid"` in `run_scenario` and in `cleanup()` kill nothing and `wait ""` is silently swallowed. Every scenario orphans one `voxis-fake-stt` (2 per run; on failure paths too). Verified on this Mac right now: `pgrep -fl voxis-fake-stt` shows **7 orphaned `target/debug/voxis-fake-stt --port 0 --map …fake-stt-map.json` processes** left by the orchestrator's/worker's runs. Masked in CI only because the docker container dies with the script. Also means the "--port 0, no port collisions" design is doing the work that cleanup should.
**Fix**: don't return the port via stdout of a subshell. E.g. have `start_fake_stt` write nothing to stdout, set `fake_stt_pid` and a global `fake_stt_port` in the parent shell (call it as a plain function: `start_fake_stt; port=$fake_stt_port`), or have the server's `listening on` line parsed into a variable *after* the function returns. Additionally harden the trap: `trap cleanup EXIT INT TERM`, and `kill` by process group or `pkill -P $$` as a belt-and-braces fallback. Orchestrator: `pkill -f 'target/debug/voxis-fake-stt'` to clean up the current leak.

### F2 — MEDIUM — speech scenario rides the `StreamDied` recovery path only; `guardOutcome` never asserted (`host-min-smoke.sh` `run_scenario "speech" … "Вот такая…" "1"`; `main.rs` autostart block)
The autostart starts a `Mode::Toggle` session and never stops it; the session ends only because the scripted `MockCapture` runs out of samples (~9.5 s), the liveness guard fires `StreamDied` after 4 missed polls, and the Recover path transcribes. So the ONE real-binary speech proof in CI never exercises the normal contract (`stop` → `Finalized` → text), and the script would pass just the same if the finalize path were broken or if the guard outcome regressed to anything else. The README's smoke description ("finalizes exactly like any other stop trigger") frames this as intended, but the plan's acceptance scenario is click → Recording → Transcribing → text, i.e. the `finalized` path. `streamDied` here is an artifact of the mock ticker, not a designed contract.
**Fix** (small): in autostart mode, after `script_len * 250 ms + ~500 ms` (host-min already knows the script length from `wav_to_level_script`) call `tauri_plugin_voxis::commands::stop(state, id)`; then assert in the script `"guardOutcome":"finalized"` for speech (in addition to the text). Optionally keep a third scenario that does NOT stop, to keep the `streamDied` recovery path covered explicitly (it is valuable — just not as the only path).

### F3 — LOW — silence scenario does not assert `text == ""` (`host-min-smoke.sh` line `run_scenario "silence" "silence.wav" "silenceTimeoutNoSpeech" "0"`)
README and the script header both claim "empty `text`" is asserted; the script only greps `silenceTimeoutNoSpeech` and the 0-request count. Add `"text":""` to the expected grep (or parse the JSON with `python3`/`jq` if available in the image; plain grep on the serde output is fine since field order is stable).

### F4 — LOW/RECOMMEND — vendored 1.7 MB `ui/vendor/voxis-overlay.bundle.js` can silently drift from guest-js
`guest-js/dist/` is gitignored (guest-js `.gitignore:7`), so the committed bundle is the only build artifact of guest-js in the repo and nothing detects drift (no CI rebuild + `git diff --exit-code`, no hash check). Not blocking (KISS for a `script-src 'self'` page is defensible), but pick one of:
 (a) gitignore `ui/vendor/`, and have `host-min-smoke.sh` (and thus the CI job) run `bun run build` in guest-js + `scripts/bundle-overlay.sh` **before** `cargo build -p host-min` (the UI dir is embedded at compile time via `frontendDist: ../ui`, so the order matters). `bun` is already in the voxis-ci image (the `fast` job runs `bun run test:run`).
 (b) keep it committed and add a CI step that regenerates and fails on `git diff --exit-code -- ui/vendor`.
(a) is cleaner and also removes 1.7 MB (incl. all themes) from every diff.

### F5 — LOW — `MockCapture` ticker is single-shot and free-running (`main.rs` `scripted_mock_capture`)
The background thread ticks every 250 ms forever and the script is consumed once; a second session in the same process would see an exhausted script and die via `StreamDied` after 1 s. Fine for the one-session smoke run, but the README says "for as long as a session is recording" — document "one session per process" or re-arm the script on `start()`. Also, because the ticker and the guard both run at 250 ms but unsynchronised, a `watch` channel can occasionally coalesce two ticks into one observed sample; harmless for peak/fraction metrics, worth a one-line comment.
